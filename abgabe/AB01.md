## 1. DAO-Pattern: create-Methode

> Erläutert das Zusammenspiel von `DaoImp`, `PatientDao` und der Datenbanktabelle `patient`, wenn die im Interface `Dao` definierte Methode `void create(T t) throws SQLException` aufgerufen wird.

DaoImp ist eine abstrakte Implementation der Data-Access-Objekt Architektur, 
welche die CRUD (Create, Read, Update, Delete) Struktur darstellt.
Sie dient dafür, die Kommunikation zwischen dem Java programm und einer Datenbank zu definieren, 
ohne das der aufrufende Code selbst Datenbank code benötigt. 
PatientDao ist die Implementation dieser Klasse zur Kommunikation mit der "patient" Tabelle.

## 2. Erweiterung um ein Pfleger-Modul

> Was müsstet ihr tun, um ein Modul zur Verwaltung von Pflegekräften zu ergänzen? Welchen Vorteil bietet die Architektur mit generischem `DaoImp<T>` gegenüber einer Architektur mit konkreten DAO-Klassen pro Model?


Für die Implementation werden die folgenden Elemente benötigt:

- Eine Erweiterung der SQL Datenbank um eine "Pflegekräfte Tabelle"
- Eine Implementation von DaoImpl namens "CaregiverDao"
- Ein neues AnchorPane welches die Pfleger darstellt und bearbeiten lässt
- Ein neuer Knopf in MainWindowView welches das Neue Panel im Center öffnet
- Die DaoFactory muss um einer Factory Methode für CaregiverDao erweitert werden.

Der vorteil von der Generischen DaoImpl Klasse ist es, dass die basis Funktionen die für jede Datenbank veränderung
benötigt werden, immer implementiert werden müssen und dass die Schnittstellen in allen Datenbank klassen gleich sind.

## 3. ConnectionBuilder, DaoFactory und das Singleton-Pattern

> Erklärt die Aufgaben der Klassen `ConnectionBuilder` und `DaoFactory`. Warum hält `PatientDao` keine eigene Datenbankverbindung? Warum sind beide Klassen Singletons?

Die DaoFactory verwaltet die Erstellung von Data-Access-Object Klassen. 
Die ConnectionBuilder Klasse verwaltet die verbindung zu der Datenbank. 

Beide Klassen nutzen das Singleton Pattern, 
wodurch nur eine Instanz von deren Klassen geladen werden.

Dies ist nützlich, weil das Konstante erstellen dieser Klassen für nicht nötige verluste bei
der Geschwindigkeit des Programmes sorgen würden. Für die ConnectionBuilder hat es auch den vorteil, 
dass das Verwalten der Externen verbindung zur Datenbank zentralisiert ist. Das Öffnen und Schließen passiert an einen einzigen ort.

Würden einzelne Dao klassen diese verbindungen selbst verwalten, könnte es leicht zu Fehlern kommen, und verbindungen würden möglicherweise nicht richtig geschlossen werden.

## 4. MVP-Pattern

> Erklärt das Zusammenspiel von `Patient`, `AllPatientController` und `AllPatientView.fxml`, wenn ein Benutzer einen neuen Patienten anlegt und auf *Hinzufügen* klickt. Worin liegt der Unterschied zu MVC?

_
Diese Komponenten sind so aufgeteilt:

View: AllPatientView.fxml
Model: Patient
Presenter: AllPatientController

Der Unterschied zu der MVC Architektur liegt darin das View und Model komplett getrennt sind.
In dem MVC Pattern kriegt die View die Model daten, in dem MVP Pattern kriegt die View ihre Daten 
von dem Presenter, welche als middleman zwischen der View und dem Model agiert.

Der Knopfdruck zum Erstellen eines Nutzers in der View übergibt dem Presenter also die Daten der View, 
der Presenter weist dann das Model an, den neuen Eintrag zu erstellen. Daraufhin übergibt der Presenter die daten, 
welche die view benötigt, um den neuen Nutzer anzuzeigen.
